# Operating Rules

## Do

- Keep changes small, focused, and consistent with the existing Astro project.
- Prefer static, accessible, readable pages over unnecessary client-side JavaScript.
- Preserve the calm engineering-notebook tone of the site.
- Keep public content company-neutral and NDA-safe.
- Add new public routes to the sitemap route when appropriate.
- Update README or topic docs when behavior, setup, or deployment changes.
- Use `npm run build` as the primary correctness check for site changes.

## Do Not

- Do not add employer names, product names, private metrics, screenshots, logs, tickets, roadmap details, or internal architecture diagrams.
- Do not add analytics, tracking, newsletters, comments, or third-party scripts unless explicitly requested.
- Do not add a resume link unless explicitly requested.
- Do not expose direct email links unless explicitly requested.
- Do not reintroduce Playbooks unless explicitly requested.
- Do not publish draft articles as live content without confirmation.
- Do not change the canonical domain away from `https://sudesh.co.in` unless explicitly requested.
- Do not perform destructive git operations.

## Handoff

When finishing, summarize:

- Files changed.
- User-visible behavior changed.
- Verification command run and result.
- Any remaining manual setup, such as DNS or Google Form changes.
